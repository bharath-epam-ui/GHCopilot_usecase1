## Tasks Completed

### TASK-01 | components/TaskCard.tsx | Inline status select control with optimistic update

**Status:** completed

**Changes made:**

1. Added `useState` and `useEffect` to the React import line (new import statement).
2. Added `TaskStatus` to the `@/lib/types` import.
3. Extended `TaskCardProps` interface with optional field:
   `onStatusChange?: (id: string, newStatus: TaskStatus) => Promise<void>;`
4. Updated function signature to destructure `onStatusChange` from props.
5. Added three local state variables: `optimisticStatus`, `isChangingStatus`, `statusError`.
6. Added a `useEffect` that resets `optimisticStatus` whenever `task.status` prop changes externally (DR-04 prop-sync).
7. Added `handleInlineStatusChange` async event handler with optimistic update, rollback on error, and 3-second auto-clear of error message (DR-02 explicit try/catch/finally, FR-05).
8. Replaced the existing `<span data-testid="task-status">` with a control group containing:
   - A `sr-only` `<span data-testid="task-status">` that preserves textContent for test assertions (DR-01, FR-04, NFR-02).
   - A `<select data-testid="inline-status-select">` with three `<option>` elements each carrying their own `data-testid` attributes (FR-01, FR-02).
   - A conditional `<p data-testid="inline-status-error">` shown on API failure (FR-05).
9. All pre-existing `data-testid` attributes (`task-card`, `task-id`, `task-title`, `task-description`, `task-status`, `task-priority`, `task-assignee`, `edit-task-button`, `delete-task-button`) remain in the DOM unchanged (NFR-02).
